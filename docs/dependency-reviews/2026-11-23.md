## Why the Dependabot PRs were red

- #773, #774 and #775 failed the quality gate's first check, "Check provider
  SDK pins against the capability manifests": the capability manifests still
  pinned OpenCode `1.19.5`, ACP `2.6.0` and Claude `0.3.323`.
- That step runs before "Verify migrations, architecture, lint, and types",
  which was skipped, so two typecheck failures never showed on those PRs:
  - #775: `SDKStartupFailureReason` gained `initialize_fields_not_delivered`,
    which the exhaustive startup-failure map must cover.
  - #774: ACP 2.8 removed the file plan representation, so the
    Cursor, Kimi and Grok harnesses' `update.plan.uri` branch reads a
    property of `never`.
- `merge-ready` failed on all three because the quality gate failed.
- #776 (`@anthropic-ai/sdk` 1.11.0) was green.

## Integration findings and fixes

1. Claude startup failures explain `initialize_fields_not_delivered` ("Claude
   Code couldn't read the settings Inertia sends when it starts. If Claude
   Code runs through a wrapper script, make sure it passes Inertia's
   arguments and input through unchanged."). Like `initialize_not_first` and
   `managed_settings_not_delivered`, it does not offer the fresh-session
   retry, which would not help.
2. Provider capability manifests pin Claude 0.3.329, Cursor, Kimi and Grok
   `acp-v1/sdk-2.8.0`, and OpenCode `opencode-owned-server/sdk-1.19.6`.
3. The Cursor, Kimi and Grok harnesses no longer have a branch for file
   plans, which the SDK now drops before they see them. They ignore
   `prompt_suggestions_update` and `cursor_update` explicitly.
4. `scripts/provider-drift-sdk-surface.ts` gains three compile-time fences:
   a disposition for every ACP session update kind, the ACP plan
   representations, and every Claude startup failure reason. The weekly
   canary now flags a new member of any of them before a Dependabot PR does.
   Removing one key fails the compile.
5. `acp-adapter-drift.test.ts` adds three scenarios, run for Cursor, Kimi
   and Grok:
   - Prompt suggestions and session cursors sent without negotiation are
     ignored, the turn completes, and `initialize` advertises neither
     capability.
   - A pre-2.8 file plan is dropped and the turn completes, while a markdown
     plan with a `path` still shows its content.
   - An agent that sends text and a plan and then exits without answering
     the prompt has both projected. The turn fails once, as a process exit
     or closed transport, and no event follows it.

## Open items for the owner

- An agent that still sends file plans loses its plan display. Inertia used
  to show "Cursor plan: <uri>" (or the Kimi or Grok equivalent). The CLIs
  Inertia supports were not checked for file plans. The weekly canary probes
  the latest Kimi and Cursor CLIs; Grok has fixture and SDK-surface coverage
  only.
- A later Agent SDK will switch `mcpServersDelivery` to `'initialize'`.
  That only matters if Inertia starts passing stdio, SSE or HTTP MCP servers
  to Claude: a Claude Code older than the SDK's bundled version would then
  refuse to start, so the floor or the option would need to change.
- `npm audit --omit=dev --audit-level=moderate` passes.
  `check:dependency-audit` passes but reports that its picomatch
  GHSA-fc5q-39xc-vjpf exception is no longer used, so it can be removed.
  None of the four bumps touches picomatch.
- The Electron end-to-end suite, packaged smokes, and the macOS and Linux
  builds run only on the PR's CI. No real Claude Code, Cursor, Kimi, Grok or
  OpenCode CLI was run against these SDKs.

## Integration and dependency scope

Inertia's native Codex provider launches the installed CLI's App Server and
speaks JSON-RPC over bounded JSONL. It does not import `@openai/codex-sdk`.
On 2026-09-30, `npm view` reports the stable `latest` tag of both official
npm packages, `@openai/codex` and `@openai/codex-sdk`, as 0.159.2;
the TypeScript SDK wraps local execution rather than replacing Inertia's
native approvals, steering, goals and control transport. No runtime dependency,
lockfile or third-party notice change is needed.

The installed Homebrew CLI on the verification host was upgraded from 0.154.0
to 0.159.0 through its owning package manager. A read-only call through the
production environment and metadata reader advertised GPT-6.1-Sol with
`low`, `medium`, `high`, `xhigh`, `max`, `ultra`, text/image inputs and the
`priority` Fast tier. No account identifiers, credentials or raw provider
output are retained here. No model turn was sent during that metadata read.

## Reviewed protocol changes

The isolated official 0.159.0 binary's
`app-server generate-ts --experimental` produced the same **85 server
notification** and **11 server request** discriminants as Inertia's reviewed
disposition tables. Experimental `currentTime/read` is included by generation;
its absence from upstream's non-experimental checked-in types is not removal.

The release adds item anchors to `thread/items/list`; Inertia persists its own
history and does not use that endpoint. `instant_interrupt` remains an opt-in
upstream feature; Inertia's exact-turn `turn/steer` receipt remains authoritative.
TUI rendering, prompt suggestions and onboarding changes do not change the
native integration.

One relevant outcome changed: the
[strict Guardian circuit-breaker](https://github.com/openai/codex/pull/48796) can emit an
`interrupted` turn with `turn.error.codexErrorInfo = "tooManyDenials"` and no
separate `error` notification. This structured error is opt-in: Codex attaches
it only when the user's Codex configuration sets
`auto_review.circuit_break_action = "strict"`. With the setting omitted or set
to `default`, Codex leaves `turn.error` unset, and Inertia still reports that
Guardian stop as a plain interruption. Inertia does not set this option.

Inertia now reports an interrupted turn that carries an error object as
failed, including an empty or unknown-shaped object, and retains a bounded,
scrubbed error detail. `tooManyDenials` is reported as "Codex stopped the turn
after repeated approval denials."; other `codexErrorInfo` values keep only
their variant name. A delegated child turn stopped this way is reported as
failed. An array, string or number in `turn.error`, a plain interruption, an
earlier retry error, and an explicit local cancellation keep their existing
cancellation semantics. Thread and turn ownership still gate the event before
classification.

  GPT-6.1 Sol/Max forwarding on a new build turn and GPT-6.1 Sol/Ultra on a

  separate current-catalog observation and portable fixtures above.

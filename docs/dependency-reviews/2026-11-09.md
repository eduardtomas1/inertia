## Integration findings and fixes

1. Claude startup failures explain `config_file_invalid` ("A Claude Code
   configuration file isn't valid JSON. Repair the file named in the details,
   then try again.") and `initialize_not_first`, which only a wrapper script
   can cause. Neither offers the fresh-session retry, which would not help.
2. `session_writes_lost` becomes a failed system activity that leaves the
   completed turn intact, because the SDK says results already received
   stand. The message names the disk error and what was lost, and falls back
   to a generic disk error for codes the SDK may add later. Claude Code sends
   it only as it exits after the last result, and Inertia stops reading at
   the result, so in practice it is rare today. Surfacing it reliably would
   need the stderr line or reading past the result: a follow-up, not part of
   this update.
3. Provider capability manifests align with the exact pins: Claude 0.3.319,
   and Cursor, Kimi and Grok `acp-v1/sdk-2.4.0`.
4. Two guard tests record that Inertia's ACP wire validation still runs before
   the SDK: batch frames are rejected, and a `subagent_update` with a
   mistyped `cwd` fails closed as `malformed-protocol`.
5. PDF.js 6.5 (#22116) asks the canvas factory for the page's opaque
   context through a new `getNoAlphaContext(canvas)` instead of calling
   `canvas.getContext("2d", { alpha: false, … })` itself, and it ignores a
   passed `canvasContext` whenever `canvas` is also given. Inertia's own
   `PdfNodeCanvasFactory` does not extend PDF.js's base class, so every
   rasterized PDF page failed with `getNoAlphaContext is not a function`:
   scanned PDFs, charts and sparse pages would have reached the agent without
   their page images. The factory now implements the method with the
   attributes 6.4 used. Eight existing `document-attachment-context` tests
   caught it and pass with the fix. The filter factory contract is unchanged.
6. The entry CSS budget grows by the measured 28 bytes.

## Provider contract drift canary

The weekly canary on main (run 42587909059) failed on two latest-release
drifts. Both are fixed here, and the probe now passes every check locally
against the latest releases, including Codex 0.167.0:

- The SDK surface script's Claude system-subtype table lacked
  `session_writes_lost`, which 0.3.319 adds. The product typecheck does not
  compile that script, so only the canary saw it.
- Codex added `thread/section/changed` (`threadId`, `sectionId | null`),
  broadcast when a thread moves into, within or out of a user-defined
  Codex sidebar section. Inertia does not use Codex sections, so it is
  `ignored`, like `thread/name/updated` and `project/changed`. The reviewed
  disposition count moves from 87 to 88.

## Open items for the owner

- Installers grow by roughly 16–21 MB from the larger bundled Claude Code
  binary. Inertia runs the user's Claude Code, so a future change could stop
  shipping the bundled binary; the release container and Windows installer
  smoke tests currently require it.
- Grok is missing from the ACP drift suite (`acp-adapter-drift.test.ts` and
  `scripts/provider-drift-sdk-surface.ts`), predating this update.

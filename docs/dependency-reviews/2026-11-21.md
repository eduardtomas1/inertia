# Dependency review — 2026-11-21

Reviewed against main `7903164d` (#745), using Node 22 on Windows x64 and the
published old/new npm package contents. The PR supersedes Dependabot #747,
which itself replaced #746 once #745 had taken `ws` 8.23.0. Both updates are
taken at exactly the versions Dependabot proposed, and the lockfile is
Dependabot's.

## Integration findings and fixes

1. xa11y 0.16's JavaScript binding takes `Rect` fields as whole numbers and
   throws `InvalidActionDataError` for a fraction, where 0.15.4 truncated
   it. Loading both win32 builds confirms it: `screenshot({ region })` with
   `y: 0.5` returns an image on 0.15.4 and throws on 0.16.1.
   `x11CaptureBounds` divided X11 pixels by the AT-SPI scale and passed the
   result as the capture region. On an X11 session scaled to 125%, 150% or
   200%, an odd window position or size therefore failed every snapshot as
   a native failure, without retry. The region is now rounded inward to
   whole logical pixels, so it stays inside the native client area, and the
   masks and node coordinates are computed against that same region. At
   100% nothing changes, which is why CI's Xvfb runs could not show it.
2. The unit test mock for xa11y refuses fractional regions like 0.16 does.
   A 200% X11 capture with odd geometry checks the whole-pixel region, the
   mask position and the unmasked pixels; it fails on the previous rounding.
   `x11CaptureBounds` is checked at 125%, 150%, 200% and 300%.
3. The renderer budgets for core JavaScript, the main workbench first load
   and the detached chat first load grow by the measured 139 bytes. The
   bundle was built with lucide-react 1.72.0 and 1.75.0 on the same tree;
   no other budget moved.

## Open items for the owner

- No snapshot was taken on a real scaled X11 desktop, a Windows UWP or
  mixed-DPI desktop, or macOS. The HiDPI failure is shown from the binding's
  validation and the unit tests, not end to end.
- GTK 4 windows with client-side decorations: 0.16 now reports their bounds
  without the shadow. Whether they match X11 geometry was not checked
  natively; if not, they keep failing as no active window, as before.
- Only the win32-x64 and linux-x64-gnu xa11y packages were unpacked. The
  darwin and arm64 binaries were covered by the PR's CI only.

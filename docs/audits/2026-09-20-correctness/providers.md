## Confirmed defects and fixes

1. **False authenticated readiness.** `src/server/provider/discovery.ts::authStateFromProbe` matched `authenticated` as a substring of `Not authenticated` and `Unauthenticated`; positive-looking historical text (and Claude `loggedIn: true`) was accepted even from unsuccessful or signal-ended status probes. Codex/Claude/Cursor could therefore show Connected and admit a turn while their connection was unconfirmed. New deterministic discovery-seam suite reproduces this without real credentials. Negative statuses now dominate legacy positive prose and positive readiness requires exit 0; Claude structured false remains authoritative. Kimi's documented runtime-auth negotiation and OpenCode configured-provider semantics were preserved. Commit **2d6e74c0**. Before: 16 of 23 new cases failed (including 13 false runnable cases; three Logged out cases were safe unknown but lacked signed-out classification). After: 37/37 passing across auth-readiness, discovery-close-race, provider-info-refresh.
2. **Queued turn permanently occupied after maintenance refusal.** TurnController persists exact provider ownership before calling ProviderRunCoordinator.run. If provider maintenance claims its installation while the queued turn awaits preparation, `acquireInstallationUse` raises expected `ProviderInstallationAdmissionError` before launch. Previously no active provider or no-start cleanup receipt existed, so stopOwned returned missing and the durable turn stayed running indefinitely; future sends stayed blocked until restart. The coordinator now records an exact no-start receipt only for this typed, known pre-launch refusal. Unexpected admission exceptions, post-start exceptions, ownership mismatches, quarantine, and missing cleanup continue to fail closed. Commit **8cadc26f**. Regression before: expected failed/turn-start-failed, observed running/null. After: 37/37 passing across admission-cleanup, controller-cleanup-proof, installation-lease. Test also proves no harness/secret launch, no release of another installation lease, wrong run receipt refusal, and immediate retry after maintenance becomes available.

## Rejected or deferred suspicions

- Follow-up acknowledged after its owner settles: rejection is intentional and explicitly tested in turn-follow-up-coordinator; no speculative persistence-after-terminal change.
- Unexpected exceptions before harness start do not synthesize cleanup proof: explicit existing safety contract; preserved. Only typed installation admission refusal was fixed.
- A successful metadata read clears metadata-local cleanup doubt: production installation quarantine is a separate authority, so it does not reopen a genuinely uncertain process installation by itself.
- Codex result/notification sharing one stdout batch, stale resume IDs, cancellation reserve exhaustion, and late provider callbacks: existing ownership/deadline code and focused fixtures cover these; no reproduced new defect.
- Empty final text versus authoritative text snapshots: snapshots have explicit deletion semantics; ordinary empty result text is not a deletion receipt. No change made without a concrete producing-provider failure.
- Kimi partial-output failures reported as end_turn: upstream protocol limitation recorded, not guessed from content.
- Abort wrapper's already-aborted promise observation was a possible exceptional dependency edge; no production timing reproduction established, so no change.

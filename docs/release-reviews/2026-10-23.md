# Windows ARM64 release review

The unpublished v0.0.76 candidate is frozen at
`2f666831964390a5af166c8eae814c80854fbb64`. The release run is
[39933796426](https://github.com/eduardtomas1/inertia/actions/runs/39933796426).
No release gate was bypassed and no asset was published. Corrections belong to
a new candidate, v0.0.77; the v0.0.76 tag is not moved.

## Failures and evidence

| Attempt | Failure | Established result |
| --- | --- | --- |

The [targeted native investigation](https://github.com/eduardtomas1/inertia/actions/runs/39989907181)
ran the original fixture three times, repeated the native terminal test ten
times without changing its deadline, and repeated the delayed-answer Electron
scenario 25 times with shutdown-owner tracing enabled. All repetitions passed.
This does not establish a fix for the original terminal or cleanup failures.

The four retained platform reports show similar CPU, memory and benchmark
results. They do not establish a generally degraded runner. Removing repeated
directory creation had no meaningful local speed benefit and was excluded.

The first macOS x64 attempt separately exceeded the 30-second packaged-readiness
deadline during final-container smoke. Its log contains GPU initialization
errors and no readiness marker; this does not prove the GPU caused the timeout.
The same container checks passed on the next attempt. No macOS startup fix is
claimed here.

## Corrections

- Join the first-client discovery result through runtime snapshots. Executable
  readiness can precede the model catalog; both must be ready before the
  history proof begins. Starting another refresh superseded the initial
  probe's publication owner and repeated its work. Exact executable checking,
  fresh model verification, saved-history assertions, speed/compaction turns,
  and the original discovery/history deadlines remain required.
- Keep the line-ending regression small. The existing native checkpoint
  benchmark now explicitly verifies the exact tracked count and empty Git
  stderr under the same line-ending configuration for the complete
  12,000-file fixture. Its five samples, ratio below six, ten-second checkpoint
  limit and existing bounded setup budget are unchanged.
- Enable the existing bounded shutdown-owner trace for the delayed-answer
  transcript scenario. Cleanup must still be confirmed; a future failure will
  retain which runtime owner blocked it instead of only a generic stop error.

## Validation

The new history regression stalls any redundant refresh while forwarding real
runtime commands and provider turns. Original code exhausts the unchanged
eight-second deadline; corrected code completes the proof. Another regression
withholds the model catalog and verifies no history command is admitted early.

Focused smoke/launch tests and the enforced full-size checkpoint benchmark
pass locally on macOS ARM64. Native validation of the corrected release
candidate is tracked by its PR and Release workflow; passing diagnostic
repetitions are not release certification.

## Declined: better-sqlite3 13.1.1 (#736)

better-sqlite3 13.1.1 bundles SQLite 3.54.1 instead of 3.53.4. Its JS API,
native source and compile options are otherwise unchanged.

- **Fixtures:** the published fixtures differ only in the header's
  last-writer version (offset 96, 3053004 → 3054001). Regenerating them would
  be correct, as it was for 13.0.3.
- **Query plans:** three history-page size queries now seek on `turn_id`
  because 3.54 folds `… OR 0`, and the plan-recovery query gains a Bloom
  filter. None got worse.
- **Why it is declined:**
  - SQLite 3.54's `whereLoopOutputAdjust()` flags every `col = ?` term that a
    plan does not satisfy through an index for re-preparation when the
    bound value changes to or from 0/1.
  - `sqlite3_clear_bindings()` ignores that 0/1 restriction and expires the
    statement whenever any flag is set.
  - better-sqlite3 calls `sqlite3_clear_bindings()` after every execution
    that binds parameters. So a statement with a bound equality plus
    ORDER BY, GROUP BY, DISTINCT or a join is compiled again on every call.
- **Measurements:**
  - A two-column `WHERE a = ? AND b = ? ORDER BY c` goes from 32 to 64 µs per
    call, which is the full prepare cost. Binding once instead brings it back
    to 33.5 µs.
  - On the seeded runtime database, the history page's 47 reads go from 2.61
    to 3.51 ms, and message search from 241 to 296 µs.
- **What would help:** no migration or query rewrite fixes it.
  `SQLITE_DBCONFIG_ENABLE_QPSG` is not exposed by better-sqlite3. 13.2.0 still
  bundles 3.54.1.
- **Decision:** take the update once a SQLite release makes
  `sqlite3_clear_bindings()` respect the restriction and better-sqlite3 ships
  it. Until then, the fixtures and snapshot stay as they are.

## Integration findings and fixes

1. Claude startup failures explain `managed_settings_not_delivered` ("Claude
   Code couldn't read the managed settings Inertia sends when it starts. If
   Claude Code runs through a wrapper script, make sure it passes Inertia's
   arguments and input through unchanged."). Like `initialize_not_first`, it
   does not offer the fresh-session retry, which would not help.
2. Provider capability manifests pin Claude 0.3.323, and Cursor, Kimi and
   Grok `acp-v1/sdk-2.6.0`.
3. Grok joins the ACP drift suite, which closes the open item from
   2026-11-09. `acp-adapter-drift.test.ts` runs every scenario for Grok too,
   with a Grok-style fixture that answers `authenticate` and
   `session/set_mode`. `scripts/provider-drift-sdk-surface.ts` pins Grok's ten
   methods and its update and prompt-result types, and the runtime probe also
   requires `authenticate` and `session.resume`.
4. A drift test sends a `tool_call` holding a valid and an invalid session
   reference plus text. The turn completes and only the text reaches the tool
   output.

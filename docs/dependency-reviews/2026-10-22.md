## Integration findings and fixes

1. electron-vite no longer provides esbuild transitively. Existing tests and
   `scripts/provider-drift-staging.mjs` import it directly. Type checking failed
   after a clean install. Declare the previously locked `esbuild@0.25.12` as a
   development dependency, restoring its reviewed platform bindings.
2. The deprecated `externalizeDepsPlugin` now rewrites `rollupOptions` from
   `rolldownOptions`. A direct Vite build in the existing guardian-integrity
   regression lost its input and failed as an SSR HTML build. Use the supported
   `build.externalizeDeps: true` option in the main, preload and runtime-status
   configurations. The existing exact sidecar/compiled-integrity test passes
   with this correction; no assertion is removed or weakened.
3. Provider capability manifests contained the previous SDK versions. Align
   their bundled versions and SDK-specific protocol identities with the exact
   installed pins. This updates capability/continuation identity digests instead
   of reporting stale verification metadata. The existing package-pin alignment
   regression detects the mismatch and passes after the update.
4. npm 10 dropped newer libc metadata while adding esbuild. Preserve the
   original Linux glibc/musl selectors from the reviewed bot lockfiles rather
   than carrying unrelated platform metadata removals.
5. Transcript and file-preview DOM geometry fixtures supplied offset sizes but
   left client dimensions at Happy DOM's zero defaults. The new virtualizer
   therefore measured a zero-height viewport and failed existing anchor and
   line-measurement assertions. Supply consistent client dimensions before
   mounting, retaining all existing positioning, virtualization and measurement
   assertions. Browser geometry remains covered by Electron CI.

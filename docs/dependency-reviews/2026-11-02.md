## Integration findings and fixes

1. Claude startup failures map `sandbox_required_unavailable` to a readable
   message, with a test.
2. Provider capability manifests align with the exact pins: Claude 0.3.314,
   OpenCode 1.19.5, Cursor and Kimi 2.1.0 (still `acp-v1`).
3. The ACP drift tests record the new contract: a usage update the ACP schema
   rejects is dropped and the turn completes without a usage event, and an
   unsafe-integer usage update still fails closed.
4. The third-party notice generator also reads `LICENSE-*` and `LICENSE_*`
   files, so the notices carry the Anthropic SDK's MIT terms beside
   Apache-2.0. The same rule adds the MIT text `emoji-regex@8.0.0` ships as
   `LICENSE-MIT.txt`, which the notices previously listed without text.
   Directories with license-like names are skipped, so a folder such as
   `license-files/` does not fail generation; licenses reached through
   `SEE LICENSE IN` keep their containment checks.
5. Renderer bundle budgets grow by the measured +335 / +343 / +47 / +308
   bytes (main workbench, detached chat, morphicons, core), from
   `virtual-core`, `lucide-react` and `morphicons`.

## Upstream documentation review

The provider documentation and changelogs were read for every provider, not
only the updated packages, against the versions Inertia supports. No provider
CLI was run; Codex and Claude Code behavior was confirmed in published source
and in the strings of the Claude Code binaries bundled with the SDK.

6. Claude Code reviews plan-mode shell commands with its auto mode classifier
   instead of the host's `canUseTool` whenever auto mode is available, and
   `useAutoModeDuringPlan` defaults to `true`. Inertia's managed settings now
   set it to `false`; the 2.1.309 binary already reads the key and honours a
   `false` from the managed and flag layers. The launch `settings` carry it
   too, because a machine with its own admin managed-settings tier drops
   host-supplied managed settings.
7. Claude's Monitor tool runs a shell command. The keyed-launch command
   refusal hook and the permission broker now cover `Monitor` beside `Bash`
   and `PowerShell`, and a Monitor approval shows its command.
8. Codex 0.166.0 (openai/codex#57840) rejects `thread/resume` and input when
   the thread's saved model provider differs from the configured provider,
   counting profiles and app-server launch overrides but not request
   overrides. Custom-backend runs and compaction now pass the provider as
   `codex app-server` `-c` overrides; the fixture applies the same admission
   rule to `thread/start`, `thread/resume` and `turn/start`. Provider ids that
   TOML would read as a number, boolean, `inf` or `nan` are refused.
9. Codex added `thread/readState/changed` (0.163), which failed the scheduled
   provider drift canary since 2026-10-19; it is listed as ignored.
10. Homebrew's `opencode` formula is 2.2.5 and no `opencode@1` exists. A
    latest version above the pinned major, or at OpenCode's unsupported
    major, is no longer reported as an update, including for installs
    Inertia cannot update itself.
11. Antigravity 1.3.3 reports an expired sign-in as "Authentication expired.
    Please log back in."; it now maps to the Connect prompt.

Reviewed with no change needed: ACP 2.1.0 against about 45 realistic Cursor
and Kimi payloads (only `usage_update` newly drops; Kimi sends integer
counts), Cursor's ACP docs, Kimi Code 2.4 (moved to `MoonshotAI/kimi-code`),
OpenCode 1.19.x and its advisories, MCP 1.32.2, Codex 0.162–0.166 additive
fields, and Antigravity headless flags and events through 1.4.12.

Open items for the owner: Claude Code before 2.1.314 can still read some
settings from files excluded by `settingSources` (fixed in 2.1.314); Claude
fast mode on Opus 4.8 is removed on 2026-11-30 and returns an error with no
fallback; MCP's 2026-07-28 revision drops the `initialize` handshake that
Inertia's host-tool server speaks, with v1 SDK support guaranteed until at
least late January 2027; Codex 0.167 adds `requiredHumanApproval` for managed
command rules; Codex native goal updates on a custom-backend chat run through
a control App Server that has neither the backend provider nor its
credential, which predates this review.

## Corrections

- Join the first-client discovery result through runtime snapshots. Executable
  readiness can precede the model catalog; both must be ready before the
  history proof begins. Starting an unconditional refresh superseded the initial
  probe's publication owner and repeated its work. A complete catalog inherited
  from N-1 is not current-process evidence: after cached startup settles, request
  one refresh and require provider provenance. A successful refresh response
  without a newly observed catalog still fails at the original deadline.
  Exact executable checking,
  fresh model verification, saved-history assertions, speed/compaction turns,
  and the original discovery/history deadlines remain required.
- Keep the line-ending regression small. The existing native checkpoint
  benchmark now explicitly verifies the exact tracked count and empty Git
  stderr under the same line-ending configuration for the complete
  12,000-file fixture. Its five samples, ratio below six, ten-second checkpoint
  limit and existing bounded setup budget are unchanged.
- Enable the existing bounded shutdown-owner trace for the delayed-answer
  transcript scenario. Cleanup must still be confirmed; a future failure will
  retain which runtime owner blocked it instead of only a generic stop error.

## Validation

The new history regression stalls any redundant refresh while forwarding real
runtime commands and provider turns. Original code exhausts the unchanged
eight-second deadline; corrected code completes the proof. Another regression
withholds the model catalog and verifies no history command is admitted early.
Cached-startup regressions require exactly one refresh after startup settles;
they reject a successful command acknowledgment that leaves only cached models.

Focused smoke/launch tests and the enforced full-size checkpoint benchmark
pass locally on macOS ARM64. Native validation of the corrected release
candidate is tracked by its PR and Release workflow; passing diagnostic
repetitions are not release certification.

## Post-merge main CI: auto-title fixture evidence

The corrected PR passed its complete native CI run
[39994738350](https://github.com/eduardtomas1/inertia/actions/runs/39994738350)
and merged as `64ab52fc6f596210bf465901facf980038f79f9a`. Its post-merge
main run [40001568728](https://github.com/eduardtomas1/inertia/actions/runs/40001568728)
then failed the macOS ARM64 isolated auto-title scenario at
`auto-chat-titles.spec.ts`: the second turn's completed status and response
were visible, but the fixture journal retained only one of two expected
`chat/turn/completed` records after the unchanged 30-second polling deadline.
The other 206 isolated scenarios passed; six were skipped.

The fixture wrote its completion records after emitting `turn/completed`.
The runtime deliberately terminates a settled Codex process immediately at
that terminal boundary (`src/server/codex/app-server-run.ts`). A controlled
execution of the actual fixture source, stopping at terminal publication,
loses both the chat-completion and title-answered records with the original
ordering and retains both with the corrected ordering. This establishes an
evidence-publication race consistent with the failed trace; the trace does
not retain the precise interrupted filesystem operation.

Persist those synthetic completion records before publishing their terminal
notifications. Keep the UI completion checks, exact record counts, title
request assertions, no-second-title interval and all deadlines unchanged.
This is a fixture correction, not a product title-generation fix. The
unpublished release tag remains unchanged until corrected main CI passes.
Both auto-title Electron scenarios passed ten repetitions each locally on
macOS ARM64 (20/20), with the original assertions and deadlines.

## 2026-10-24: diagnostic setup and overlapping ACP credentials

The corrected candidate at `3262f37a957a910fb8a50d2c3a12b8a75c125861`
passed main CI but its release run
[40013283533](https://github.com/eduardtomas1/inertia/actions/runs/40013283533)
failed the Windows ARM64 watcher-note response assertion. macOS ARM64
required forced termination after confirmed privileged cleanup in two cases,
missed a Duo verdict, and then reached its job deadline before retaining the
failed traces. Those original native failure causes remain unproven. Passing
focused repetitions and the subsequent full desktop diagnostic sequence are
non-reproductions, not fixes or permission to publish.

The first unit-prefix diagnostic run replaced the release workflow in its
checkout. Ten workflow-contract assertions correctly rejected that diagnostic
file. The probe now restores the exact frozen release workflow before unit
tests read it; it does not skip or weaken those contracts. Its observation
flag was also renamed from `INERTIA_DIAGNOSTIC_KEEP_PASS=1` to
`INERTIA_DIAGNOSTIC_RETAIN_BASELINES=1`. The former name was classified as a
credential environment variable, introducing the synthetic secret `1` into
ACP redaction tests. With the frozen contract and neutral flag, all 81 focused
contract/redaction cases passed locally (one platform case skipped).

That flag exposed a separate real redaction defect. The original bridge suite
passes all ten cases without it and fails four with it. Cursor and Kimi first
masked each notification payload, then passed its text delta to the streaming
redactor. Masking a shorter overlapping credential inside a delta breaks the
longer bridge credential across deltas, allowing its prefix into emitted
replies or reasoning. A second final-flush defect preferred a complete short
credential over a significant held prefix of a longer credential.

Preserve validated text deltas until the existing boundary redactor consumes
them, while redacting surrounding notification metadata as before. On final
flush, redact the full significant held prefix before considering a shorter
complete match. Credentials are still registered and masked; no secret value
is excluded from the inventory. New deterministic prefix, suffix and
single-character overlap cases exercise every bridge split, replies,
reasoning, successful completion, trailing prefixes and provider cancellation
for both adapters. All nine new cases fail before the correction and pass
afterward; the focused three-file redaction suite passes 46 cases locally.
This correction does not claim to fix the original native watcher, Duo or
Electron-exit failures. The unpublished tag and existing draft remain frozen
while those investigations continue.

Node 22 `npm run check` passes 1,310 files and 15,929 tests, including lint,
